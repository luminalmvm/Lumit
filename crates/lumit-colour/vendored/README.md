# Vendored reference bakes

Tier two of `BuiltinTransform` handling (docs/impl/ocio.md §4.1). The OCIO v2
ACES configs express their output transforms as **code names** — "ACES-OUTPUT —
… SDR-VIDEO" — not as data, so there is nothing in the config file to read. The
design's answer is to generate those transforms once, offline, with the
reference OpenColorIO library, and check the resulting artefact in like any
other golden data.

**Nothing is vendored yet.** A style with no bake here and no direct
implementation in `src/builtin.rs` refuses by name, which is the correct
behaviour rather than a gap being papered over. `src/builtin.rs` carries the
loader; this directory carries the data when someone with the reference library
generates it.

## What a bake must carry before it can land here

One file per style, in the format `bake::VendoredArtefact` reads (`to_text` /
`from_text`), whose header lines are the provenance:

```
lumit-colour artefact 1
# style: ACES-OUTPUT - ACES2065-1_to_CIE-XYZ-D65 - SDR-VIDEO_1.0
# generated by: OpenColorIO <version>, <how it was invoked>
# generated from: <config, at <version>>
# generated on: <date>
# input domain: shaper lg2, min <n>, max <n>, offset <n>
shaper lg2 -8 5 0.00390625
cube 65
…
```

A file without those lines is not a golden, it is a table somebody found. The
same run must also produce `tests/fixtures/aces-cg.fixture`, so the bake and the
rows that prove it agree come from one place and one version.

## Why the bakes are not simply approximated in Rust in the meantime

Because a wrong picture that looks plausible is the one failure this crate is
built to refuse. An exact Rust port of each style is recorded follow-up work,
one style at a time, each landing against these same fixtures — at which point
the style moves from tier two to tier one and the vendored file becomes the test
data that proves the port.
