# The websites: web/ and web-docs/

Two small Astro sites. They live in the repo but outside the Cargo workspace, and
nothing depends on them (K-279). You can change either without touching the app.

| Directory | Site | Stack |
|---|---|---|
| `web/` | lumitlab.com — the marketing site and release notes | Astro 5 + Tailwind 4 |
| `web-docs/` | docs.lumitlab.com — the user manual | Astro 5 + Starlight |

## Astro in one minute

An `.astro` file has two parts: a frontmatter script between `---` fences that runs
**at build time**, then markup below it.

```
---
const releases = await getCollection("releases");
---
<h1>{releases.length} releases</h1>
```

Routing is by file path: `src/pages/download.astro` serves `/download`.
`src/pages/releases/[...id].astro` is a dynamic route — one page per collection
entry. Layouts and components are just `.astro` files you import.

Both sites build to static HTML. There is no server. The only dynamic thing on
either site is a client-side fetch on the download page.

## web/ — the marketing site

```
web/
  astro.config.mjs        site URL, static output, Tailwind plugin
  wrangler.jsonc          Cloudflare Worker: serve ./dist as static assets
  src/content.config.ts   the releases collection and its schema
  src/content/releases/   one Markdown file per release
  src/layouts/Base.astro  the page shell
  src/components/         Header, Footer, Wordmark, ReleaseEntry, ReleaseDate
  src/pages/              index, download, 404, releases/
  src/styles/global.css   design tokens and component classes
  public/                 files served as-is (the mark and wordmark SVGs)
```

The download page fetches
`https://api.github.com/repos/luminalmvm/Lumit/releases/latest` in the browser and
inserts the version, date and asset links. A failed or rate-limited fetch leaves the
static fallback text in place. A release tag therefore updates the site with **no
deploy**.

## web-docs/ — the manual

Starlight supplies the whole shell: sidebar, search, table of contents, dark mode,
edit links, and per-page "last updated" dates from git history.

```
web-docs/
  astro.config.mjs         title, logo, social, editLink, sidebar
  src/content/docs/        every page: start/ use/ panels/ engine/ reference/
  src/components/          PageTitle, LastUpdated, Shot
  src/assets/shots/        screenshots, plus a README listing wanted ones
  src/styles/theme.css     Starlight colour variables matched to the app
```

Pages are `.md` or `.mdx`. Use `.mdx` when the page needs a component such as
`<Shot>`. Use plain `.md` otherwise.

## Task: publish a release note

Create `web/src/content/releases/<version>.md`. **The filename is the URL and the
version**: `0.2.0.md` serves `/releases/0.2.0`. Do not add a leading `v`. Do not use
any other name. `scripts/discord-release.mjs` reads exactly this path when the
release workflow announces a build.

Copy `_template.md` (the underscore keeps it out of the collection) and fill the four
required fields. A real entry:

```yaml
---
title: Lumit v0.2.0
description: Expressions, lens flares, update directly from the app, and updated installers for macOS and Linux.
versionNumber: 0.2.0
date: 2026-08-08
---
```

| Field | Purpose |
|---|---|
| `title` | Page heading and `<title>` |
| `description` | Page description and social card text |
| `versionNumber` | The pill on the left rail. No leading `v` — the page adds it |
| `date` | Sorts the index, newest first |

The body is plain Markdown. `.release-prose` in `global.css` styles every element, so
write content, not markup. The index page and `/releases/<version>` appear
automatically.

## Task: add a docs page

Create the file under the section it belongs to — `src/content/docs/use/`,
`panels/`, `engine/`, `start/` or `reference/`. **The sidebar is autogenerated per
directory**, so a new file appears with no config edit. Ordering inside a section
comes from frontmatter:

```yaml
---
title: Masks
description: Cut a layer down to a shape you draw.
sidebar:
  order: 10
---
```

If the page needs a screenshot, make it `.mdx` and import the component:

```
import Shot from "../../../components/Shot.astro";
```

Follow the app's own rules in prose. The [glossary](../01-GLOSSARY.md) terms are
binding on the manual too. The voice is British English, sentence case, calm.

## Task: add a screenshot

Drop the image into `web-docs/src/assets/shots/` with the exact filename the page
asks for. Nothing else changes — `Shot.astro` globs that directory at build time.
Until the file exists, the page shows a labelled placeholder that names what it wants.
`src/assets/shots/README.md` lists every outstanding screenshot with its page and
subject. PNG, JPEG, WebP and AVIF all work. Capture at the size you actually use the
app, because the page scales down.
(I had to add the eager param since astro's audit tool called it out, basically this
is used to eager load the first image on a page, since otherwise it lays the page out
then loads the image and has to do more re-arranging afaik)

```
<Shot file="timeline-outline.png" caption="The outline columns." eager />
```

## Task: change navigation

| What | Where |
|---|---|
| Marketing header links | the `links` array at the top of `web/src/components/Header.astro` |
| Marketing footer links | the same pattern in `web/src/components/Footer.astro` |
| Docs sidebar sections | the `sidebar:` array in `web-docs/astro.config.mjs` |
| Docs page order within a section | `sidebar.order` in that page's frontmatter |
| Docs social links, edit link, logo | the `starlight({ ... })` options in `web-docs/astro.config.mjs` |

To add a new docs *section*, add a directory under `src/content/docs/`. Then add one
`{ label: "...", autogenerate: { directory: "..." } }` entry to the sidebar array.

## Task: change colours, fonts or spacing

The marketing site defines everything in one place, `web/src/styles/global.css`:

```css
@theme {
  --color-ink:      #0a0b0d;
  --color-fg:       #f4f6f8;
  --color-key-cy:   #86e2ff;
  --font-sans: "Schibsted Grotesk Variable", ui-sans-serif, system-ui, sans-serif;
```

This is Tailwind 4, where the theme lives in CSS via `@theme` rather than in a
`tailwind.config.js`. A token named `--color-ink` creates the utility classes
`bg-ink`, `text-ink`, `border-ink`. Reusable pieces (`.card`, `.btn`, `.pill`,
`.wrap`) are defined once under `@layer components`.

The docs site maps the same ramp onto Starlight's variables in
`web-docs/src/styles/theme.css` (`--sl-color-bg`, `--sl-color-accent`, …). Change
both if a colour must match across the two sites. Fonts are self-hosted
`@fontsource-variable` packages — never a font CDN.

Both sites are hex-literal territory, unlike the app: the no-hex lint covers
`crates/` and `flutter_ui/lib`, not `web/`.

## Commands

```bash
cd web && npm install && npm run dev
```

```bash
cd web-docs && npm install && npm run dev
```

`npm run dev` serves with live reload. `npm run build` writes `./dist` and fails on
schema errors and broken internal links. `npm run preview` serves the built output.

Deployment is Cloudflare's git integration: push to the production branch and each
site builds and deploys itself. Pushes to other branches get preview URLs. You do not
run `wrangler deploy` by hand in the normal flow.

## Traps

- **The release filename is an interface.** `scripts/discord-release.mjs` reads
  `web/src/content/releases/<version>.md` during the release workflow. A renamed or
  missing file means the announcement fails.
- **A missing or misspelt frontmatter field fails the build.** The schema in
  `content.config.ts` validates every entry. `date` must parse as a date.
- **Do not slugify version filenames.** The loader keeps dots deliberately, so
  `0.1.0.md` serves `/releases/0.1.0` rather than `/releases/010`.
- **Files starting with `_` are excluded** from the releases collection. That is how
  `_template.md` stays out.
- **Docs deploys need full git history.** Starlight's per-page dates come from git.
  A shallow clone makes every page read as "updated today".
- **Tailwind 4 has no config file.** Editing a `tailwind.config.js` does nothing —
  the theme is the `@theme` block in `global.css`.
