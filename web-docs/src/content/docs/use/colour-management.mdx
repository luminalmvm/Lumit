Lumit composites in **scene-linear Rec. 709**, in floating point, whatever your footage
arrived in.

Without a configuration Lumit uses its own built-in handling — it reads what the file says
about itself, and shows you the working space encoded to sRGB. An **OpenColorIO
configuration** is for when that is not enough: log footage, a show with its own looks, a
delivery that has to match somebody else's.

## Choose a configuration

**File ▸ Project settings… ▸ Colour** holds one row, **Configuration**, with *Choose…* and
*Clear* beside it.

Under the row is a line saying what happened. Read and in use, it counts what it found —
*Loaded: 42 colour spaces, 3 displays*. Named but not usable, it says why in one sentence.
A configuration asking for something unimplemented is refused rather than approximated.

There is no separate relink. *Choose…* is also how you point at a configuration that moved.

Below it, **Working space** states what the arithmetic runs in. It is a reading, not a
choice: v1 fixes it at linear Rec. 709 whatever the configuration says, and bridges to the
configuration at the edges.

The configuration is a property of the **project**, saved in the `.lum` and undoable like
any other edit. A missing or unusable configuration never stops a project opening: the
preview falls back to the built-in handling, the picker says so, and every colour-space name
you assigned is kept exactly where it was.

## Say what a footage item arrived in

Right-click a footage row in the [Project panel](/panels/project/) and open the **Colour
space** submenu.

- **As the file says** is where every item starts. Lumit interprets it the built-in way,
  from what the file itself states.
- Under **From the configuration** are the configuration's own colour-space names, in its
  own words. Pick the one the footage was shot or graded in.

This changes pixels, so it is saved in the project and travels with it.

## Look at it through a view

The Viewer bar carries a **colour-pipeline picker**. Its closed face names what you are
looking through.

| Face | Means |
| --- | --- |
| **Linear → sRGB** | The built-in transform. What you get with no configuration, and what you come back to. |
| ***view* — *display*** | A view out of the configuration, on one of its displays. |
| **Config not in force** | The project names a configuration, it cannot be used, and the built-in transform is standing in. The reason is in the menu. |

Open it and the built-in transform is the first row, then one heading per display the
configuration knows about with that display's views beneath it. **Tone mapping** sits at the
foot, if you have turned its button on in Settings.

Tone mapping and the Viewer's exposure box are **ways of looking**. They never reach an
export, and while either is engaged the badge says *preview*.

## Writing it out

The export dialogue's **Colour** section gains the configuration's spaces in its **Colour
space** list, under a *From the configuration* heading, beside the built-in ones. **Managed
by** reads the configuration's path; it is a reading, and Project settings is where it
changes.

Two things worth knowing before you deliver:

- A file written through the configuration's transform is left **untagged** rather than
  mis-tagged.
- An export naming a space this build cannot transform to is **refused**, not written
  wrongly.

:::note[Not built yet]
A configuration whose own working space Lumit adopts, context variables, the grading
transforms, inverting a 3D look-up table, and a standalone looks picker are not built.
Lumit's own perceptual work — the blend modes and the tone-map curve — reads pixels as
Rec. 709 whatever the configuration's primaries are.
:::
