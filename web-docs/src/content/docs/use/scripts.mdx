A **script** is a JavaScript file that edits the open project. After Effects scripts
(`.jsx`) run as they are.

## Run one

1. Choose **File ▸ Run script…**.
2. Pick the `.js` or `.jsx` file.

While it runs, a card covers the window with the script's name and **Stop**. A file the
script asks for opens the system file dialogue, and a message it shows appears in the
status line.

The whole run is one undo step, named after the first name the script gives
`app.beginUndoGroup()`, or after the file. A script that fails or is stopped leaves the
project as it was.

When a script fails, the status line gives the reason and the line it failed on.

### Where Lumit differs

- A Bezier key with no ease of its own is automatic. Spatial tangents are not carried, so
  a point moves between keys in a straight line.
- `valueAtTime()` reads between eased keys in a straight line.
- Roving keys stay at their times.
- Key times land on the nearest frame of the comp.
- A 3D layer's X, Y and Z Rotation are turned into Lumit's rotation order. The layer
  matches After Effects on every key.
- Orientation is set once. Keys on it stop the script.
- A layer given a `parent` stays where it is at the comp's start.
- `app.newProject()` answers the open project.
- `activeItem` is the comp open in the Viewer. On the command line it is the project's only
  comp, or null when there are more.
- An expression is JavaScript. While it is on, the keys under it are not kept.
- An effect Lumit does not have stops the script. Controls named by number or match name take
  After Effects' values and convert them as importing does. By name, they take Lumit's own.
- A marker keeps its comment, duration, label colour and whether it is a chapter. Chapter
  text, URLs and cue points are not kept.
- A numbered still always imports as the whole sequence.
- A footage item's `duration` is known once it has a layer.
- An item's `comment` and a comp's or solid's pixel aspect are not kept.
- `#target` lines are skipped. `#include`, `//@include` and `#includepath` read in files from
  the script's own folder and the folders inside it, each once.
- A script's window is drawn with Lumit's own controls. Fonts, colours and places are not
  kept, and sizes, `margins` and `spacing` are taken roughly. A palette waits as a dialog
  does.
- Escape or the close mark presses a window's Cancel button, or makes `show()` answer 2.
- On the command line and over MCP, `show()` answers 2 at once.
- A script reads and lists files in its own folder and the folders inside it, and files you
  chose or passed to it. A script at the top of a drive or in the home folder itself has no
  folder of its own. Anywhere else `exists` is false.
- A script writes text files, as UTF-8, only in its own folder and the folders inside it, and
  never over the project. A run writes at most 64 MB. A script with no folder of its own, as
  over MCP, writes nothing.
- A script imports footage only from the files it can read. It saves the project over its own
  file or as a new `.lum` file, and exports, only into the project's folder or its own, never
  over a file.
- A network path or a device is refused.
