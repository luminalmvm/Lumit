A **script** is a JavaScript file that edits the open project. After Effects scripts
(`.jsx`) run as they are. A script also runs Lumit's own commands, listed in the
[Scripting reference](/reference/scripting/).

## Run one

1. Choose **File ▸ Scripts ▸ Run script…**.
2. Pick the `.js` or `.jsx` file.

A script dropped on the window runs after one question, **Run** or **Cancel**.

While it runs, a card covers the window with the script's name and **Stop**. A file the
script asks for opens the system file dialogue, and a message it shows appears in the
status line. One script runs at a time. A script file is at most 16 MB.

The whole run is one undo step, named after the first name the script gives
`app.beginUndoGroup()`, or after the file. A script that fails or is stopped leaves the
project as it was.

When a script fails, the status line gives the reason and the line it failed on.

When a script prints with `print()`, `console.log()` or `$.writeln()`, or shows an
`alert()`, **Show log** on the status line lists the lines, with **Copy**. Alerts come after
the printed lines. A right-click on a line has **Copy line**. The log keeps 10,000 lines and
1 MB, and a line is cut at 4 KB.

## The Scripts folder

**File ▸ Scripts** lists the `.js` and `.jsx` files in the Scripts folder, with a submenu
for each folder inside it, four folders deep and 500 scripts at most. A file or folder whose
name starts with a dot is left out. **Open scripts folder** shows the folder in the file
manager.

| | |
|---|---|
| Windows | `%LOCALAPPDATA%\Lumit\Lumit\data\scripts\` |
| macOS | `~/Library/Application Support/dev.Lumit.Lumit/scripts/` |
| Linux | `~/.local/share/lumit/scripts/` |

**Settings ▸ General ▸ Scripts folder** lists another folder instead, picked with
**Choose…**. **Clear** goes back.

## Event scripts

The **Scripts** rows in **Settings ▸ General** run a script from the Scripts folder after an
event. Each is **None** until set.

| Row | Runs after |
| --- | --- |
| **Export finished** | each export from the export queue |
| **Project opened** | a project opens |
| **Project saved** | the project is saved |

It runs as from the menu, and the status line names it after.

| | |
| --- | --- |
| `lumit.args.event` | `"export"`, `"open"` or `"save"` |
| `lumit.args.file` | the exported file's or the project's file name, without its folder |

An event script is skipped while another script runs or a card covers the window, and the
status line says so. A script's own saves and exports, an export made for a shared preview,
and the save made before a project closes, run none.

## What a script may reach

- A script reads and lists files in its own folder and the folders inside it, and files you
  chose or passed to it. A script at the top of a drive or in the home folder itself has no
  folder of its own. Anywhere else `exists` is false.
- A script reads at most 64 MB from one file, and is told of at most 100,000 entries in one
  folder.
- A script writes text files, as UTF-8, only in its own folder and the folders inside it, and
  never over the project. A run writes at most 64 MB. A script with no folder of its own, as
  over MCP, writes nothing.
- A script imports footage only from the files it can read. It saves the project over its own
  file or as a new `.lum` file, and exports and saves frames, only into the project's folder
  or its own, never over a file.
- A network path or a device is refused.
- A script's values take at most 1 GB of memory.

On the [command line](/use/command-line/#run-a-script), a script's saves, footage and
exports go where it says.

### Where Lumit differs

- A Bezier key with no ease of its own is automatic. Spatial tangents are not carried, so
  a point moves between keys in a straight line. The spatial tangent calls answer zeros.
- `valueAtTime()` reads between eased keys in a straight line.
- Roving keys stay at their times. A key's continuous setting is kept only to be read back.
- Key times land on the nearest frame of the comp. Of two keys set on one frame, the later
  is kept.
- `setValue()` on a property that has keys stops the script.
- Anchor Point's third value has to be 0 and Scale's 100. Orientation other than 0 on a 2D
  layer stops the script.
- A camera a script adds, and a layer it makes 3D, turn in After Effects' rotation order and
  keep their X, Y and Z Rotation as they are. On a 3D layer in Lumit's order they are turned
  into that order, which matches After Effects on every key.
- `autoOrient` is `CAMERA_OR_POINT_OF_INTEREST` or `NO_AUTO_ORIENT` on a camera, and
  `NO_AUTO_ORIENT` on any other layer.
- A layer given a `parent` stays where it is at the comp's start.
- `app.newProject()` answers the open project.
- `activeItem` is the comp open in the Viewer. On the command line it is the project's only
  comp, or null when there are more.
- `addComp()` files the comp where it is asked for, not in the Compositions folder.
- An item's `id` and a layer's `id` are Lumit's own, as text. An item's `remove()` is not
  supported.
- An expression is JavaScript. While it is on, the keys under it are not kept.
- An effect Lumit does not have stops the script. Controls named by number or match name take
  After Effects' values and convert them as importing does, and read as empty until the
  script sets them. By name, they take Lumit's own.
- A marker keeps its comment, duration, label colour and whether it is a chapter. Chapter
  text, URLs and cue points are not kept. A marker set on a frame that has one replaces it.
- `importFile()` imports as footage only. A file Lumit cannot read stops the script.
- A numbered still always imports as the whole sequence. `mainSource.isStill` is always false.
- A comp's or solid's pixel aspect is not kept.
- `#target` lines are skipped. `#include`, `//@include` and `#includepath` read in files from
  the script's own folder and the folders inside it, each once, 16 deep and 16 MB at most.
- A file opens to read, write or append. What is written reaches the disk when the file is
  closed or the script ends. On Windows a path written `/c/folder` is read as `C:\folder`.
- A script's window is drawn with Lumit's own controls. Fonts, colours and places are not
  kept, and sizes, `margins` and `spacing` are taken roughly. A palette waits as a dialog
  does. A script is never handed a dockable `Panel`.
- Enter presses a window's `defaultElement`, or its button named or labelled OK. Escape, a
  click beside the window or the close mark presses its `cancelElement` or its button named
  or labelled Cancel, or makes `show()` answer 2.
- On the command line and over MCP, `show()` answers 2 at once.
