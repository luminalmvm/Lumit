A **project** is the complete document: assets and compositions, together with
their settings. It is saved as a `.lum` file.

<Shot file="recovery-dialog.png" caption="The crash-recovery dialogue, offering the journal, the newest autosave, or the saved file." eager/>

The project file stores references to footage files, and Lumit never modifies those files.
A [packed project](#packed-projects) also carries the files themselves.

## Save and open

- **File ▸ Save** saves the project.
- **File ▸ Save as…** saves to a new path. If already saved, it creates a new copy at the location.
- **File ▸ Open project…** opens a `.lum` file, **Open recent** lists the last few.

With unsaved changes, Lumit asks before the project goes: on **New**, **Open project…**,
**Open recent**, **Close project**, an After Effects import, and on quitting. **Save** saves
first, **Discard** drops the changes, and **Cancel** keeps the project open. If the save is
cancelled or fails, the project stays open.

## Packed projects

A packed project carries its footage inside the `.lum` file. It opens on a machine that has
none of the original files. The commands are under **File ▸ Packed project file**.

- **Pack project file** saves the project with every footage item's file inside it. Footage
  imported afterwards is not packed until the command is run again.
- **Pack automatically** packs on every save.
- **Unpack project file** writes the packed footage into a `media` folder beside the project
  and saves the project without it. A footage item whose original file is still on disk
  goes back to reading that file, and nothing is written for it.

A packed footage item reads its original file while that file is on disk and unchanged.
Otherwise it reads the packed copy, which is copied into Lumit's cache when the project opens.
A file that has changed on disk since it was packed is packed again on the next save.

:::note
Proxies and the files effects read, such as a LUT, are packed with the footage, and so is
the OCIO config with the look-up tables in its folder. Autosave copies hold the document
only, and an autosave reads its footage from the project file it was written beside.
:::

## Shared projects

A shared project is edited by several people at once. One person, the **host**, shares it
from their computer and the others join as **guests**. Guests connect to the host's
computer directly, over a local network, the internet or a VPN, or through a relay. A
shared project can also be [kept online](#keeping-a-shared-project-online).

**File ▸ Shared project…** opens the **Shared project** window, which has two pages.

- **Share this project**: **Start sharing** shares the open project and shows its
  **invite link**.
- **Join a project**: an invite link is pasted, and **Join** opens the host's project in
  place of the open one.

A click on an invite link in a browser opens Lumit on **Join a project** with the link
filled in. On macOS the link is pasted by hand.

While a project is shared, a **Shared** button sits on the bottom strip and opens the same
window. It lists everyone in the project. The host can **Remove** a guest, and **Stop
sharing** ends it for everyone. A guest has **Leave**.

An invite link holds every address the host can be reached at and a key. Anyone who has it
can join and edit until the host stops sharing. A link is not drawn until it is shown. **Show**
asks before it shows one, and **Copy link** copies it without showing it. The part of the link
after the `#` is not sent to lumitlab.com.

**Password** on **Share this project** sets a password that every guest types as well as
having the link. **Join a project** shows a **Password** row for a link that needs one. A
wrong password and a host that is not there give the same message. A project shared again
keeps its password unless another is typed.

A guest tries every address in the link at once and keeps the one that answers with the
key. The line under the link says who it works for.

| Line | Who can join |
| --- | --- |
| Anyone you send this link to can join. | Anyone. The host's router opened the port, or a relay is in use. |
| Only people on your own network can join with this link. | People on the host's network. The router refused, has no address of its own on the internet, or was not asked. |

**Advanced** holds the rest.

- **Internet**: when ticked, Lumit asks the host's router to open the port when sharing
  starts, and to close it when sharing stops. It is ticked by default.
- **Port**: the port the host listens on.
- **Relay**: the address of a relay, for guests the router does not let in.
- **Address**, while sharing: one more address to add to the link, such as a VPN's.

### Relays

A relay is a server that passes edits between a host and its guests when neither can reach
the other. Both connect out to it. What passes through is encrypted with the invite's key,
which the relay is never given. The relay's owner can see the addresses that connected and
how much was sent.

**Lumit relay** on **Share this project** uses the relay Lumit itself runs. It is part of
[Lumit Pro](/use/profiles/#lumit-pro): the host needs it, and guests do not. It is used when
**Relay** is empty.

Any other relay is used only when its address is in **Relay**. It
is the `lumit-relay` program from Lumit's source, run on a server its owner controls:
`cargo run --release -p lumit-relay`, with a port number after it to listen on a port other
than 47857. A second number is a speed in kilobytes a second that each connection is held
to after its first 16 MB, which lets edits through and slows footage. A guest is sent
through the relay only when no address of the host answers.

An edit made by one person appears for everyone. Two people can work on the same layer at
once: a change to one effect, mask or property leaves the others as they are. Where two
people change the same value, the later change stands. Undo takes back a person's own
edits, and skips a step that another person has changed since.

The host's project file is the one that is saved. A guest's copy is a new, unsaved project.

Each person has a colour, and what they have in hand is marked in it.

| Panel | What is marked |
| --- | --- |
| Project | A dot on a composition they have open, and a bar on the items they have selected. |
| Timeline, Audio timeline | A bar on the layers and property rows they have selected, a ring round the keyframes they have selected, in the layer view and the graph view, and a line at their playhead. |
| Effect controls | A bar on an effect they have picked and on a row they have pressed. |
| Node graph | A ring round a box they have picked. |
| Viewer | Their pointer. |

A row out of sight in a layer that is twirled shut is marked on the layer. Two people on the
same row or keyframe both show.

The eye on a person's row in the people list of the Shared project window follows them. The
open composition and the playhead go where theirs go, and the Viewer shows a frame in their
colour with a **Following** tab that names them. Moving the playhead, opening another
composition, **Esc** or **Stop** on the tab stops it, and so does their leaving. Following
selects nothing and edits nothing.

A guest chooses a **Footage folder** when joining, and each footage item is matched to a
file in it by name and then by content. An item with no match can be relinked, or fetched
from someone who has it.

### Footage someone has not got

A footage item used in a composition that is not on a computer is sent to it as a
**stand-in**: the whole clip at its own size and length, with its sound, compressed hard.
The computer reads the stand-in as if it were the file. The row wears a **stand-in** badge
in the Project panel. A still or a sound file is sent as it is.

Whoever has the original makes the stand-in when it is first asked for, and the host
passes it on to a guest who asks. A stand-in is kept and is not sent twice. A transfer
that is cut off carries on from where it stopped.

On a footage row nobody here has, the menu has **Get a stand-in** and **Fetch the
original**, which fetches the file itself. A fetched original is checked against the
project's record of the file.

**Advanced** in the Shared project window holds the rest. The two limits are also in
**Settings ▸ General ▸ Shared projects**.

- **Send stand-ins of my footage**: when unticked, this
  computer sends none of its own footage.
- **Get stand-ins of missing footage**: when unticked, nothing is fetched until it
  is asked for from the menu.
- **Upload limit** and **Download limit**: the fastest footage is sent and fetched, in
  kilobytes a second. 0 or empty is no limit. Edits are not limited.

While footage is crossing, the Shared project window lists each transfer and how far
along it is.

### Exporting without the originals

The export dialogue shows **Missing footage** when the composition uses footage the
computer has no original of.

| Choice | What happens |
| --- | --- |
| **Fetch the frames this export uses** | Whoever has each clip sends the run of frames the export reads, at delivery quality, and the export starts when they have arrived. The sound comes with them. |
| **Fetch the originals** | The files themselves are fetched first. The size shown is their total. |
| **Export on someone's computer** | A person who has every clip is asked to export. Their Lumit asks them first, exports, and sends the file back to the path chosen here. |
| **Export from stand-ins** | The export reads the stand-ins as they are. |

The frames are a re-encode of the original, as H.264 at 4:2:0 and eight bits, not a copy
of its bytes.

### When the host goes away

A guest that loses the host keeps working. When the host is reachable again the guest's
edits are merged into the host's project. An edit to something another person also changed
is held back and listed in the **Conflicts** window, where each is settled with **Keep
mine** or **Keep theirs**. An edit to something that no longer exists is dropped.

A guest's saved copy that is closed while the host is away is still a guest when it is
opened again. It opens with the edits made while away that were saved, or all of them if
Lumit crashed, looks for the host, and merges when it finds it. **Leave** ends that. A
conflict not settled before the copy is closed is listed again when it is opened.

A host that closes the project, or Lumit, without **Stop sharing** keeps its invite. When
it opens the project and shares it again on the same port, the guests who are waiting come
back by themselves and their edits are merged. If the host's address has changed, a guest
pastes the new invite under **New invite** in the Shared project window.

A host keeps every edit made since its last save, its guests' included. If it closed
without saving, or Lumit crashed, **Start sharing** puts those edits back. Closing a host
project that was never saved stops sharing.

**Stop sharing** finishes with the invite, and sharing again makes a new one. **Remove**
replaces the invite. The removed guest keeps its copy, the invite it holds stops working,
and the guests still connected carry on. A guest that had lost the host at that moment
needs the new invite.

### Keeping a shared project online

A shared project can be **kept online**. Lumit's server holds it and puts everyone's edits
in order, and nobody's computer has to be on for the others to work. It is part of
[Lumit Pro](/use/profiles/#lumit-pro): the host needs it, and guests need no account.

| Action | How |
| --- | --- |
| Keep the open project online | Tick **Keep online** on **Share this project**, then **Start sharing**. |
| Join | An invite link pasted on **Join a project**, then **Join**. |
| Let someone look and not change | Turn on **Invite to look**, for the host, and send them that link. |
| Leave a note | The line at the top of **Activity**, then **Send**. |
| Open it again | Open the saved project file. |
| See who edited it | **Activity** in the Shared project window. |
| Remove someone | **Remove** on their row, for the host. |
| Stop | **Stop keeping online**, for the host. A guest has **Leave**. |
| Stop one whose file is gone | **Stop keeping online** on **Settings ▸ Account**, for the host. |

**Password** works as it does for any shared project. The people list shows who the host is
and the composition each person has open, and a composition's name opens it.

Someone who joins by **Invite to look** sees the project and the people, can follow, and is
seen. An edit made on their computer is undone at once and reaches nobody. They are marked
**look only** in the people list, and their own bottom strip reads **Look only**. They fetch
footage and send none. **Remove** replaces both invites.

**Invite to look** is off for a new project, and its link opens nothing. The switch on its
row turns it on and off, for the host. Other windows read **off** on the row while it is
off. Turning it off removes everyone who is looking, and asks first while someone is. Each
keeps their copy. Turning it on again brings back the same link.

**Invite to look** never asks for the password. With a password set, a lock marks **Invite
to edit**, and turning **Invite to look** on asks first: while it is on, either link shows
the project without the password, changing it still needs the password, and the lock
reads **to edit**. Up to eight
people can look at once, and someone who can edit takes the place of the last of them when
the project is full.

While someone changes a property, its row in the Timeline and in **Effect controls** is
held for them on every other computer. It is dimmed, carries their name in their colour and
takes no input until they let go. A row is held while a control on it is dragged or typed
in, while a menu or a picker opened from it is up, while its keyframes are dragged in the
lanes or the graph, while the layer's handles are dragged in the Viewer, and while the
layer's bar is moved or trimmed. A held row's keyframes, its handles in the Viewer and its
layer's bar cannot be dragged either, and the bar is dimmed under their name as the row is.
A row left with nothing done to it for 30 seconds is let go.

The first line of the window says how the computer stands with the server, and the bottom
strip says the same.

| Line | Meaning |
| --- | --- |
| In step | The computer has every edit, and the server has every edit made on it. |
| Looking for the server | The server cannot be reached. Edits are kept on the computer and merged when it is found, with conflicts listed in the **Conflicts** window. |
| Invite replaced | The host made a new invite while the computer was away. Edits are kept on the computer and merged when the new invite is pasted under **New invite**. |
| On hold | The host's Lumit Pro has ended and the server takes no edits. Edits are kept on each computer and merged when it takes them again. |
| Nearly too large | The project has grown past the 95 MB the server stores, footage not counted. Edits still go in, and stop unless the project gets smaller. |
| Too large | The server takes no more edits, and edits are kept on each computer. The project cannot be made smaller while it is kept online: the host stops keeping it online, makes it smaller and keeps it online again. |
| On Lumit 0.6.0, Waiting for the host, Update needed | Another version of Lumit keeps the project. See [After an update](#after-an-update). |

**Activity** lists who edited the project, newest first: each run of one person's edits
with no gap of more than ten minutes, with when it was, how many edits it held and the
compositions they were in. A composition's name opens it. The newest twelve are listed, and
**Show all** lists the rest, up to 200.

A run with edits made while the computer was not in the project is listed first, over a
rule, with the rest under **Seen**: before it joined, while its copy was closed, or while
the server could not be reached. The bottom strip says so once when the computer joins or
comes back, such as *Ana made 34 edits in Titles*, and pressing that opens the window.

A note is written on the line at the top of **Activity**. It carries the composition that
is open, the time the playhead is at and the layer that is selected, and pressing those
under a note goes there. Notes are listed among the runs of edits by when they were
written, and one left while the computer was not in the project is listed over the rule.
The bottom strip shows a note from someone else as it arrives. A note with a composition
has a flag on that composition's time ruler at its frame, in its writer's colour: pointing
at the flag shows the note, and pressing it opens the window. A note written while the
server cannot be reached reads **not sent yet**, and is sent when it is found. A note holds
500 characters and cannot be changed, and the newest 200 are kept. The cross on a note's
row takes it down for everyone, with its flag, and it cannot be put back. Its writer has
the cross on their own notes, and the host on every note, where Lumit asks first for
someone else's. Someone who joined by **Invite to look** reads notes, writes none and
takes none down.

Edits of the computer's own are dropped when it comes back and what they changed is no
longer there. A notice gives how many and stays until it is dismissed or the window is
opened. The count heads **Activity**, with what each of the first twenty was and the
composition and layer it was to.

When edits are dropped or conflicts are left, Lumit keeps the project as it was on the
computer just before. **Open my copy**, on that row and in the **Conflicts** window, opens
it as a project of its own, saved beside the shared project's file, or in a place chosen
then when that has none. Lumit keeps two such copies at most: the first that has not been
dismissed, and the latest. Each has a row of its own, with the edits that were dropped when
it was kept, and two are offered by their times. Dismissing the first row deletes both.

A copy that has been saved is still in the project when it is opened again, however it was
closed. It looks for the server and takes the edits made since. A copy that was never saved
leaves the project when it is closed, and the project stays online.

**Remove** asks first. It takes a person out and replaces the invite link. Everyone
connected at that moment gets the new link by themselves. Anyone else needs it from the
host. Their window reads **Invite replaced** when their computer is back, and the new link
is pasted under **New invite**. The removed person keeps their copy and the footage they
had fetched.

An invite that opens nothing says why on **Join a project**: the project is no longer kept
online, the invite was replaced, or the invite to look is off.

**Stop keeping online** asks first. The server deletes the project and its footage, the
project stays on the host's computer, and every other copy becomes an ordinary project.

**Settings ▸ Account** lists every project the account keeps online under **Kept online**,
with how much the server holds for it and when it was last opened. A project is named by
its file on the computer that put it online, and is otherwise **Unnamed project** with the
day it was put online. **Stop keeping online** is there for each. **Storage** on the same
page is what backups and footage kept online have used.

Footage is kept on the server too. Each computer sends a stand-in of the footage it has
that a composition uses, and fetches a stand-in of what it lacks. The switches and limits
under **Advanced** apply. The window lists each file being sent or fetched, how far along it
is and what failed. The cross on a row stops that file, and a file that failed has a mark
that tries it again.

- **Keep the originals online**, in the host's window: the host's computer also sends the
  original files. Unticked, its label gives the size that would be sent.
- **Fetch the original**, on a footage row's menu: fetches the file from the server. The row
  reads **Original not online yet** when the server has none.

Footage counts against the host's Lumit Pro storage. When the storage is full, no more is
sent. The window says so, with **Manage…** for the host, which opens **Settings ▸ Account**,
and **Try again**. Lumit asks the server again every five minutes.

The project, the footage, each person's name and what they have selected are encrypted on
the computer they come from. The key is in the invite link and is never sent to the server.
The server sees the addresses that connect, the version of Lumit, how many edits are made
and how large each is, and for each footage file its size and a hash of part of it.

When the host's Lumit Pro ends, the server stores nothing more. What it holds can still be
opened and fetched. A project nobody opens for 90 days after that is deleted from the
server.

#### After an update

A project kept online is on the version of Lumit that last stored it, and a computer on
another version is not in step with it.

| Computer | What happens |
| --- | --- |
| The host's, on a newer Lumit | Lumit asks once whether to move the project forward. **Move it forward** does that, and the project carries on. **Not now** leaves it, and the Shared project window offers the move again. |
| A guest's, on a newer Lumit | The copy waits, and joins by itself when the host has moved the project forward. |
| Anyone's, on an older Lumit | The window names the version the project is on, with the button **Help ▸ Check for updates** has. |

Edits made on a computer that is waiting are kept on it and merged when it is in step
again. A move cannot be undone. It is refused while someone on the older Lumit goes on
editing, and when the newer Lumit cannot read an edit the older one stored. The project is
then unchanged.

:::note
Everyone needs the same version of Lumit. Image sequences, proxies, files an effect reads
such as a LUT, and the results of tracking, roto and depth analysis are not sent. A proxy is looked for in the
footage folder as footage is, and a file an effect reads by its name at the top of that
folder. A shared project takes up to 16 people.
:::

## Autosave

Lumit keeps rotating autosave copies in an `autosaves/` folder beside the project. They
are written on an interval while the project has unsaved changes, and again before risky
operations such as starting an export. The interval and how many copies are kept are both
under Settings, on the Autosave page; turning the interval to zero switches the timer off.
A project that has not changed since its last save or autosave writes nothing.

## Crash recovery

Between saves, Lumit also records every edit. After a crash, open the project and Lumit
asks whether to restore them. **File ▸ Recover…** asks again later. The dialogue has
three choices:

| Choice | Recovers |
| --- | --- |
| **Restore all changes** | Everything up to the moment things stopped. |
| **Restore latest autosave** | The project as it was at the last autosave. |
| **Don't restore changes** | Nothing. The project stays as it was opened. |

The command is live once the project has been saved to a file, and does nothing while
there is no autosave beside it. After a crash, an answer other than **Restore all
changes** throws the recorded edits away.
