Lumit is an **OpenFX host**. Plugins you have installed for other applications are found on
start-up and offered beside the built-in effects, and behave exactly like them.

<Shot file="effects-presets-ofx.png" caption="A plugin's own heading in the Effects & presets panel, under the built-in categories." eager/>

## Where Lumit looks

The standard OpenFX locations, scanned once at start-up:

| Platform | Directory |
| --- | --- |
| Windows | `C:\Program Files\Common Files\OFX\Plugins` |
| macOS | `/Library/OFX/Plugins` |

Anything on the `OFX_PLUGIN_PATH` environment variable is scanned too.

The scan runs in the background, so a machine with a large suite installed does not open any
slower. Install a plugin while Lumit is running and it appears the next time you launch.

A plugin Lumit cannot drive is one line in the scan report, never a dialogue. The scan
carries on, and the other plugins in the folder are unaffected.

## Where they appear

In the [Effects & presets](/panels/effects-presets/) panel, under the plugin's own declared
grouping as a heading of its own. A plugin declaring no grouping goes under **Plugins**.

From there it groups, folds, searches, stars and drags exactly like a built-in. The one
difference is a provenance line at the top of its right-click menu: *From an OpenFX plugin*.

## Switch one off

**Switch this plugin off**, on the plugin's right-click menu in that panel. It stops being
offered and stops rendering, and the choice is remembered between sessions.

Switching one off takes effect immediately. Switching one back on may need a restart before
it is offered again, because a plugin that was off at start-up was never opened.

Any effect already in a project using a switched-off plugin is **kept exactly as it was
saved**, values and all, and renders as if it were not there.

## When something goes wrong

Each plugin bundle runs in a **process of its own**, so a plugin that crashes takes down its
own process and nothing else. The frame it was in the middle of comes back unchanged, the
layer still composites, and Lumit carries on.

The effect's card in [Effect Controls](/panels/effect-controls/) says which of four things
happened, calmly, at the top:

| Badge | Means |
| --- | --- |
| **This plugin did not render this frame** | It crashed, hung, or refused. The plugin's own words about it are printed underneath. |
| **This plugin is switched off** | You switched it off. |
| **This plugin is not installed on this machine** | The project uses it and this machine has no plugin for it. Nothing is lost. |
| **This build does not know this effect** | The project names something this build of Lumit has never heard of. |

A plugin that wants to say something — an error, a warning, a question — gets a **notice on
the status line**, never a modal window.

:::note[Not built yet]
Lumit's own native plugin interface is specified and not built. There is no Settings page
listing what is installed, and no command to rescan without relaunching.
:::
