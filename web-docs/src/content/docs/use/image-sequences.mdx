A folder of numbered stills imports as **one footage item**, and behaves like any other
footage from then on.

## Import a run

1. **File ▸ Import**, or drag onto the Project panel.
2. Pick **any one file** of the run.

Lumit reads the folder round the file you picked and imports the whole run as a single
item. Picking a different frame of the same run imports the same item.

What is recognised as a run:

- **Still-image formats only.** A folder of `clip0001.mp4`…`clip0100.mp4` is a hundred
  footage items.
- **The frame number is the longest run of digits in the name.** `shot_v2_0043.exr` is frame
  43 of version 2, not frame 2.
- **Padding has to match.** `%04d` does not name `frame7.png`, so a differently-padded
  neighbour is a different run.
- **A numbered still with no numbered neighbours** stays the single still it is.
- **A `%` anywhere in the path** refuses the run outright.

## Gaps end a run

Given `0001` to `0100` with `0050` missing, picking `0007` imports `0001`–`0049`, and
picking `0060` imports `0051`–`0100`. A gap is never bridged.

## The rate

Stills carry no frame rate of their own, so the project has to say. Every sequence starts at
**25 fps**.

:::note[Not built yet]
There is nowhere to change a sequence's rate yet, so a 24 fps render conforms at 25 and
runs a little short.
:::

## The files are the truth

Where a run starts, how long it is and which files are in it are **read from the folder
every time the project opens** — none of it is stored. Add frames to the folder and the
item is that much longer next time.

The project stores the path of the run's **first file**.

## Relinking

Relink a sequence by pointing at **any frame** of it.

## From After Effects

Sequences in an imported After Effects project come across as sequences.
