A theme is two small text files, each written like CSS. A **colour scheme** sets the
colours. A **style** sets the shape: corners, gaps, fonts, and how each part of the
interface is dressed. The two are chosen apart in **Settings ▸ Appearance**.

<Shot file="make-soft-glass.jpg" caption="A style with frosted panels and raised controls." eager/>

## A colour scheme

```css
@name "Harbour";
@base nocturne-dark;

:root {
  --accent: #3fa7d6;
  --socket-number: #ffd166;
}
```

- `@name` is its name in the **Colour scheme** list. Without it, the file's name is used.
- `@base` is the built-in scheme it starts from. A colour the file leaves out is the base's.
  Without it, the base is `dark`.
- Each `--name: #rrggbb;` sets one colour. `#rgb` is read too, `#rrggbbaa` sets its opacity
  as well, and a percentage after a colour scales it, as `#000000 60%`.
- `var(--name)` reads another colour, the file's own or the base's.
- `/* ... */` is a comment.

Case and hyphens in a name are ignored: `text-primary` and `textPrimary` are one colour, and
`nocturne-dark` and `Nocturne dark` one scheme.

The file is a `.lumtheme`. **Your themes ▸ Import…** reads one and **Export…** writes the
colours in use as one, holding only those that differ from the base. A theme file written in
JSON by an older Lumit still opens. A file with no `@base` Lumit knows and no colours is
refused.

## A style

```css
/* Harbour: rounder and softer, with the Timeline set apart */
@base lantern;

:root {
  --control-radius: 4;
  --card-radius: 20;
  --tile-gap: 14;
  --window-inset: 14;
  --sans: "Segoe UI";
}

pane            { background: var(--surface1) 85%; border: 1 #ffffff14; shadow: 0 8 24 #00000066; }
timeline pane   { background: var(--surface2); border: 1 var(--accent) 50%; }
button          { radius: round; }
button:hover    { background: var(--accent) 30%; }
well            { radius: 8; border: none; shadow: inset 0 1 3 #000000aa; }
tab:on          { background: var(--accent) 35%; }
```

<Shot file="make-style-harbour.jpg" caption="The Harbour style above, over Lantern."/>

A style is a `.lumstyle` file in the styles folder, or in a folder of its own inside it
beside its pictures and fonts. **Settings ▸ Appearance ▸ Your styles ▸ Show folder** opens the
folder: `%APPDATA%\lumit\styles` on Windows and `~/.config/lumit/styles` on macOS and Linux.
Each style is listed in **Style** under the three built in, by its file's name. Lumit
redraws when a style's file is saved.

`@base` is the built-in style it starts from: `studio`, `desk` or `lantern`. Without it,
the base is `studio`. A line Lumit cannot read is skipped, and **Your styles** shows the
first, such as `Line 4: there's no setting called colr`.

### Variables

`:root` sets the style's variables. Every one is optional.

| Variable | What it sets |
| --- | --- |
| `--control-radius`, `--float-radius`, `--card-radius` | Corners of controls, menus and panels |
| `--section-radius`, `--action-radius`, `--well-radius`, `--content-radius` | Corners of sections, buttons, value boxes and layer bars |
| `--pill-inset` | The gap between a pill and the fill inside it |
| `--card-padding` | The space inside a panel that stands on the room, round its contents |
| `--tile-gap`, `--window-inset` | The gap between panels and round the window |
| `--card-shadow` | The shadow under Lantern's panels, written as a rule's `shadow` |
| `--stroke-weight` | The icons' line weight |
| `--label-case` | `caps`, `lower` or `sentence` |
| `--title-centred` | Whether a panel's title sits centred on its strip |
| `--header-dot` | Whether a panel's header has a dot before its title |
| `--roomed` | Whether panels stand apart on the room |
| `--tabular-numbers` | Whether numbers are set in the sans typeface, with figures of one width |
| `--sans`, `--mono` | The two typefaces, by name: installed on the computer, bundled with Lumit, or carried by the style |
| `--kicker-tracking`, `--kicker-size` | The spacing and the size of panel labels |
| `--kicker-mono` | Whether panel labels are set in the mono typeface |
| `--room` | A colour, or a picture as `url("room.jpg")` |
| `--room-blur` | How far a room picture is blurred |
| `--icons` | A folder of icons, as `url("icons")`. See [Make an icon set](/make/icons/). |
| `--backdrop` | `tint` or `blur`. See [See-through windows](#see-through-windows). |

A number may end in `px`. A switch is `true` or `false`, or `yes` or `no`. A `url()` is read
from the style's folder.

A colour from the colour scheme, such as `--accent` or `--surface1`, set here replaces the
scheme's while the style is in use. `var(--name)` reads any variable or colour.

### Fonts

`@font-face` carries a typeface in the style's folder, and `--sans` or `--mono` names it.

```css
@font-face { font-family: "Fira Sans"; src: url("fonts/FiraSans-Regular.ttf"), url("fonts/FiraSans-Medium.ttf"); }
:root      { --sans: "Fira Sans"; }
```

- `src` takes one file or several, one for each weight. A variable font holds every weight in one.
- TTF and OTF are read, and collections of either. WOFF and WOFF2 are not.
- The base's typeface stands in until the style's has loaded.
- A font file that is missing or of another kind is skipped, as a line Lumit cannot read is.
- A font travels with the style when it is shared, so its licence must allow that. The SIL
  Open Font License does.

### Rules

A rule is a part, the properties to set on it, and optionally where and when:

```css
part { property: value; }
panel part:state { property: value; }
```

| Part | What it is |
| --- | --- |
| `pane` | A panel's box |
| `header` | A panel's title line |
| `tab` | A panel's tab |
| `button` | A button, including dropdowns and the menu bar's names |
| `well` | A value box or a text field |
| `menu` | A menu or a dropdown list |
| `row` | A row in a menu |
| `dialog` | A dialogue, and the Settings window |
| `tooltip` | A tooltip |

A name before the part limits the rule to inside it: `timeline button` dresses only the
Timeline's buttons. The names are `menu`, `dialog`, `menubar`, `toolbar` and the panels:
`project`, `viewer`, `timeline`, `effect-controls`, `effects-and-presets`, `scopes`,
`grade`, `debug`, `hierarchy`, `easing`, `graph`, `node`, `mixer`, `audio`,
`audio-timeline`, `cut-timeline`, `text`, `paragraph`, `expressions`, `stagger`, `notes`,
`align`, `extension` and `retime`.

`*` stands for any part, and a comma sets one rule on several: `button, tab { radius: 6; }`.

| State | When |
| --- | --- |
| `:hover` | The pointer is over it |
| `:pressed` | It is held down |
| `:on` | It is the one in force: a fronted tab, a ticked button, a picked row |
| `:disabled` | It can't be pressed |
| `:focus` | It has the keyboard |
| `:active` | A panel that has the focus |

A button also takes `.primary` for the one filled action in a window and `.dropdown` for a
dropdown's face.

| Property | Value |
| --- | --- |
| `background` | A colour, or `none` |
| `border` | A width and a colour, as `1 #ffffff22`, a colour alone for a width of 1, or `none` |
| `border-colour` | A colour |
| `radius` | A number, or `round` for a capsule |
| `shadow` | `x y blur spread colour`, with blur and spread optional. Several are separated by commas. `inset` casts one inwards. `none` takes them off. |
| `colour` | Its words and icons |
| `blur` | How far what is behind it is blurred |

`color` and `border-color` are read as `colour` and `border-colour`. A colour is written
as in a colour scheme, and `none` and `transparent` are see-through.

Of two rules that set the same property, the one naming more wins: `timeline button:hover`
over `button:hover` over `button`. A state or `.primary` counts for more than a panel's name,
so `button:hover` wins over `timeline button`. Of two that name as much, the later wins.

## Glass

A see-through `background` with a `blur` frosts whatever is behind the part. Panels stand on
the room, and menus, dialogues and tooltips over the panels.

```css
:root  { --room: url("room.jpg"); --room-blur: 40; }
pane   { background: #ffffff 9%; blur: 28; border: 1 #ffffff2e; }
menu   { background: #1b1b1e 55%; blur: 30; radius: 16; shadow: 0 18 40 #00000080; }
button { background: #17171a; radius: round; shadow: 0 3 8 #00000070, inset 0 1 0 #ffffff1a; }
well   { background: #0d0d0f 80%; border: none; shadow: inset 0 2 4 #000000b8; }
```

<Shot file="make-glass-menu.jpg" caption="The Layer menu frosting the panels under it."/>

A blurred part's shadow is drawn round it and never under it. **Reduce transparency** in
**Settings ▸ Appearance** draws every part solid and blurs nothing.

:::note
Panels paint their own fills inside the box, so the glass shows round them.
:::

## See-through windows

`--backdrop` makes the window see-through wherever the room is. `tint` takes the colour of the
desktop, softly. `blur` blurs whatever is behind the window.

```css
:root { --backdrop: blur; --room: #0b0b0e 30%; }
pane  { background: #16161a 62%; border: 1 #ffffff26; }
```

The room is clear, or the colour `--room` gives it. A style with a backdrop is roomed unless it
sets `--roomed: false`.

| System | `tint` | `blur` |
| --- | --- | --- |
| Windows 11 | Mica | Acrylic |
| Windows 10 | Blur | Blur |
| macOS | Window background | HUD |
| Linux, KDE Plasma | Blur | Blur |

The window stays solid with **Reduce transparency** on, with transparency switched off in
Windows or macOS, and on Linux desktops other than KDE Plasma.

## Sharing

A colour scheme travels as its `.lumtheme` file. It is taken in by a double-click or
**Your themes ▸ Import…**, and is in use at once. One with the name of a theme already
there comes in under that name and a number.

A style travels as one `.lumstyle` file. **Your styles ▸ Make a package** packs the style in
use into one, with the pictures, icons and fonts in its folder. A style is taken in by a
double-click, a drop on the window or **Your styles ▸ Import…**, and is in use at once.
**Undo** on the status line puts the look before it back. A zipped style folder is read too,
and a style file in a folder of its own name comes with the folder. A style of the same name
is replaced after a question.

A style package holds at most 4,096 files and 512 MB. One holding a link, or a file that
would land outside its folder, is refused. Files whose names start with a dot are left out
of a package.
